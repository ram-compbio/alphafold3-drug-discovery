# AlphaFold 3 compound–protein interaction workflow

Repository prepared from the supplied research scripts for manuscript reproducibility. Script names, algorithmic steps, input and output formats, queue thresholds, and AF3 SLURM template commands are retained. This is an **archival workflow**, not a general-purpose turnkey AF3 installation.

## Workflow

1. `af3_generation/_scripts/1_prepare_smiles.py`: merge compound identifiers and SMILES data.
2. `af3_generation/_scripts/2_prepare_input_jsons.py`: generate protein–ligand JSON inputs and reference A3M paths.
3. `af3_generation/_scripts/3_generate_slurms.py`: make one SLURM script per interaction.
4. `af3_generation/_scripts/4_submit_slurms_{cb,ea,gc}.py`: submit cluster-specific batches.
5. `af3_generation/_scripts/5_find_failed.py`: check missing/incomplete output.
6. `af3_generation/_scripts/6_cleanup.py`: remove files/directories outside expected per-protein naming.
7. `af3_generation/_scripts/7_completed.py` and `7_completed.slurm`: count completed interactions.
8. `af3_generation/_scripts/8_sync.py`: synchronize output between clusters.

Support utilities and cluster-specific templates are retained in `af3_generation/_scripts/`.

## Installation

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Only `pandas` is imported as a non-standard Python package by the supplied Python scripts. The original package version is unknown. For archival reproducibility, capture the **actual original environment** (Python version, `pip freeze`, AF3 image digest, AF3 code revision, model parameters, database versions, JAX/CUDA/GPU platform, and seeds). `requirements.txt` does not install AF3, SLURM, or cluster system tools (`sbatch`, `squeue`, `ssh`, `scp`, `rsync`, `jq`, `nvidia-smi`, `bc`). Do not assume AF3 scores are identical between versions or accelerator systems.

## Expected workspace

The numbered scripts use **relative paths and must be launched from `af3_generation/_scripts/`**. The expected layout is:

```text
workspace/
  _scripts/                      # this repository's scripts directory
    drugbank-v2.8-approved.tsv   # needed by step 1; stage here
    drugbank-v2.8-approved_smile.tsv  # needed by step 2; stage here
    all_all.smi                  # needed by step 1; not in supplied archive
    interaction_template.slurm   # provided in the package
    lists/completed.tsv          # needed by selected submit scripts; not supplied
  input_jsons_no_interactions/   # pre-existing protein JSON files
  input_jsons/                   # JSONs created by step 2
  slurms/                        # generated by step 3
  output/                        # AF3 results
  run_alphafold3                 # external wrapper; not supplied
```

The supplied DrugBank TSV and metadata tables are staged separately for deposition in Dryad; move/copy the required TSVs into `af3_generation/_scripts/` to match the original scripts' relative lookup. Step 2 expects `input_jsons/` to already exist. The original archive does not include enough inputs to reproduce a complete run.

## Execution

From `af3_generation/_scripts/` using the same input files and execution environment as the experiment:

```bash
python 1_prepare_smiles.py
python 2_prepare_input_jsons.py
python 3_generate_slurms.py
# SLURM submissions must use a valid local queue, account, and GPU setup.
python 7_completed.py
```

The generated SLURM template invokes `../../run_alphafold3` relative to each protein job directory. Verify cluster layout and AF3 wrapper configuration before submission. The `interaction_template.slurm` includes destructive cleanup of incomplete run folders; `6_cleanup.py` is also destructive. Test on copied data, never directly on archival results.

For synchronization, supply `AF3_LOCAL_ROOT`, `AF3_REMOTE_ROOT`, and `AF3_REMOTE_HOST` as the original cluster endpoints, optionally including `user@` in the host. `af3_generation/_scripts/8_sync.py` requires those variables and preserves its original transfer and file-count logic. The former hard-coded locations were removed. It still relies on site-specific queue settings.

## Known archival limitations

- `templates/3_generate_slurm.slurm` references `3_generate_slurms_trial.py`, absent from the supplied archive. The runnable Python generator is `3_generate_slurms.py`. This legacy template was not changed.
- `4_submit_slurms_ea.py` and `4_submit_slurms_gc.py` invoke `find_completed()`, which reads `lists/completed.tsv`; that file was not provided. `4_submit_slurms_cb.py` does not call it.
- Step 1 writes `drugbank-v2.8-approved_smile2.tsv`, while step 2 reads `drugbank-v2.8-approved_smile.tsv`. The original names are preserved and the two steps are **not automatically chained**.
- Step 3 references template files directly in `af3_generation/_scripts/`, so the provided interaction template was also copied to that location.
- Script 8 and the optional utility scripts contain historical cluster assumptions; they are site-specific rather than portable.
- Output equivalence has not been established by executing AF3 jobs or running an end-to-end test. Syntax checks and file-content comparison are supplied instead.
